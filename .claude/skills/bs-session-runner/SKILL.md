# Aeterna session runner

The repo CLAUDE.md is the source of truth; this skill only orders its steps. Do not re-read CLAUDE.md (it loads automatically).

## Start (one call each, condensed output)
0. Auto mode ("idle chain", rules: `docs/ai/next-session-prompt.md`). Scheduled runs: right after `add_repo` and BEFORE the clone run `gh api repos/odinguard009/aeterna/contents/tools/session_gate.sh --jq .content | base64 -d | bash -s check` (from their prompt); anything but GO = end the run at once. Manual sessions skip `check`. The owner commands `otomatis on|off|status` run the same one-liner with `on`, `off` or `status` (no clone) and end there.
1. `add_repo` odinguard009/aeterna (push access), then ONE light sparse clone exactly as CLAUDE.md says (generous timeout, never two git operations at once), then `register_repo_root`.
2. If `docs/ai/chain-stop.md` exists: stop at once unless the owner is present and has answered (then delete the file and continue).
3. `bash tools/session_start.sh`. Exit 3 / `OVERLAP` (an active `LOCK`/`MANUAL` on issue #1; fallback when gh fails: a `v*` release commit under 30 minutes old) = another session is running: stop and tell the owner. Then mark the session: scheduled runs `bash tools/session_gate.sh lock`, manual sessions `bash tools/session_gate.sh manual` (exit 3 = an auto session holds the lock: stop and tell the owner). A crashed session's mark expires (LOCK 5 h, MANUAL 3 h).
4. Context in one call: `git log --oneline -5`, open issue titles (`gh api "repos/odinguard009/aeterna/issues?state=open" --jq '.[] | "#\(.number) \(.title)"'`), newest handoff comment of the roadmap issue.
5. Schedules are not touched by sessions (one recurring task, installed by the owner; `docs/ai/next-session-prompt.md`). Never call `create_trigger`, `update_trigger` or `delete_trigger`.
6. Read `docs/ai/roadmap-open.md`, size the session (small bundle of 3-5, or one heavy task alone) and open with ONE Indonesian line: `Ver. X.Y.Z (rencana) - gunakan model Opus - <scope> - Token awal: <the total_tokens value shown at the start of the session>` (pick the work from `docs/unlock-report.md` when the plan in `roadmap-open.md` leaves a choice) (owner, 2026-10-17: Opus for every session and subagent). If the running model differs, say so once and continue (the main model cannot be switched mid-session). 
7. Every 3rd session or before a minor release: player-view pass first (skill `bs-playwright-tester`).

## During
- Per task: test/scenario first for a new mechanic, `npm run -s loop`, one commit + version bump, `git fetch origin main` + rebase before every push. Scheduled runs: before starting the next task run `bash tools/session_gate.sh switch`; OFF = no new task, go to End.
- A task that fails twice is dropped, named in the release notes and recorded in `docs/ai/roadmap-open.md` as `blocked (reason, date)`, so the next run takes another item and never repeats it blindly. If every open item is blocked, commit `docs/ai/chain-stop.md`.
- Past ~80 calls: push, handoff comment (done / next / failing seed / tokens used so far), stop and `bash tools/session_gate.sh unlock` (manual and scheduled); the next run continues.
- Usage / quota / rate-limit error: do not retry and do not touch schedules; push what is committed, handoff comment, `bash tools/session_gate.sh unlock`, stop.

## End (in this order)
1. Release gate per `docs/ai/release.md`: dispatch Regression, wait with the one-line poll in `docs/ai/token-economy.md`, read only failing lines.
2. `python3 tools/unlock_report.py` (refreshes `docs/unlock-report.md`). Update `docs/roadmap-data.json` (statuses, `updated`, `next`), the `**Done:**` / `**Next:**` lines of the CLAUDE.md Roadmap (`session_start.sh` prints the Next line, so a stale one misleads the next session) and delete finished items in `docs/ai/roadmap-open.md`; `node tools/gen_roadmap.mjs`, final commit + push.
3. Backup (owner: every 5 releases, not every session, not every commit): newest backup `B=$(git ls-remote --heads origin 'backup/*' | sed 's#.*refs/heads/##' | sort -V | tail -1)`; releases since then `gh api repos/odinguard009/aeterna/compare/$B...main --jq '[.commits[].commit.message | select(test("^v[0-9]"))] | length'` (chore/docs commits do not count). Due when it is >= 5: `git push origin HEAD:refs/heads/backup/vX.Y.Z`. A UI change keeps its own backup of the previous state (CLAUDE.md). Not due: run step 4 with `--no-backup`. Branch housekeeping: keep the newest 3 `backup/v*` branches; older ones whose tip is on `main` are listed with name + SHA in `docs/ai/deleted-branches.md` (restorable with `git push origin <sha>:refs/heads/<name>`); the session proxy blocks branch deletion, so the owner deletes them on GitHub.
4. Deliver the game: copy `index.html` to `/mnt/user-data/outputs/aeterna-vX.Y.Z.html`, then `node tools/session_end_check.mjs` (game file + embedded version, `test:release` on it, mind map fresh, `backup/vX.Y.Z` on origin; `--no-backup` only when no backup is due). It must pass; then SendUserFile that HTML **and** `docs/roadmap.html` to the owner (owner, 2026-10-16: the playable file must always be sent, not only the mind map). Do not close the session before both files are sent.
5. No scheduling: sessions never create schedules; the next session is either the owner's "Lanjutkan roadmap" or the auto run 30+ minutes later (when the switch is ON). Commit `docs/ai/chain-stop.md` only when the roadmap is empty or every item is blocked.
6. Every session, after both files are sent: `bash tools/session_gate.sh done vX.Y.Z next=Opus` (always Opus since 2026-10-17; this starts the 30-minute idle timer; `unlock` instead on an early stop or error). Name the session "Ver. X.Y.Z" (if no rename tool exists, start the final message with `Ver. X.Y.Z`). Short Indonesian summary that shows `Playable: X / 8,041` (from `tools/unlock_report.py --line`), `Token terpakai: <Token awal minus the total_tokens value left now>` (read the counter after the last tool call; it is the budget-counter difference, effective tokens incl. cache re-reads, so it can differ from the billed figure; the owner can run skill `explain-usage` for a breakdown) and the line `Mode otomatis: ON|OFF` (from `bash tools/session_gate.sh switch`), and ends with the next session's model hint `gunakan model Opus` (read the next item in `roadmap-open.md`: heavy = Opus, small bundle = Sonnet); after the release, stop (questions go to a new session).
