# Aeterna session runner

The repo CLAUDE.md is the source of truth; this skill only orders its steps. Do not re-read CLAUDE.md (it loads automatically).

## Start (one call each, condensed output)
0. Auto mode ("idle chain", rules: `docs/ai/next-session-prompt.md`). Scheduled runs: right after `add_repo` and BEFORE the clone run `gh api repos/odinguard009/aeterna/contents/tools/session_gate.sh --jq .content | base64 -d | bash -s check` (from their prompt); anything but GO = end the run at once. Manual sessions skip `check`. The owner commands `otomatis on|off|status` run the same one-liner with `on`, `off` or `status` (no clone) and end there.
1. `add_repo` odinguard009/aeterna (push access), then ONE light sparse clone exactly as CLAUDE.md says (generous timeout, never two git operations at once), then `register_repo_root`.
2. `bash tools/session_start.sh` (since v0.69.3 it also prints the chain-stop state, `Mode hemat` and an open handoff newer than the last release; P0 B3). `CHAIN-STOP` = stop at once unless the owner is present and has answered (then delete `docs/ai/chain-stop.md` and continue). `OPEN HANDOFF` = continue from it first. Exit 3 / `OVERLAP` (an active `LOCK`/`MANUAL` on issue #1; fallback when gh fails: a `v*` release commit under 30 minutes old) = another session is running: stop and tell the owner. Then mark the session: scheduled runs `bash tools/session_gate.sh lock`, manual sessions `bash tools/session_gate.sh manual` (exit 3 = an auto session holds the lock: stop and tell the owner). A crashed session's mark expires (LOCK 5 h, MANUAL 3 h).
4. (Folded into step 2 in v0.69.3: `session_start.sh` already prints `git log -5`, the open issues, the last Regression and the handoff; no separate context call.)
5. Schedules are not touched by sessions (one recurring task, installed by the owner; `docs/ai/next-session-prompt.md`). Never call `create_trigger`, `update_trigger` or `delete_trigger`.
6. Read `docs/ai/roadmap-open.md`, size the session (small bundle of 3-5, or one heavy task alone) and open with ONE Indonesian line: `Ver. X.Y.Z (rencana) - gunakan model Opus - <scope> - Token awal: <the total_tokens value shown at the start of the session>` (pick the work from `docs/reports/unlock-report.md` when the plan in `roadmap-open.md` leaves a choice) (owner, 2026-10-17: Opus for every session and subagent). If the running model differs, say so once and continue (the main model cannot be switched mid-session). 
7. **Lane session** (owner says "Lanjutkan roadmap ui" or "... card"; P1, `docs/ai/lanes/README.md`): step 3 becomes `bash tools/session_start.sh --lane <lane>` and `bash tools/session_gate.sh manual <lane>` (scheduled: `lock <lane>`); the opening line says `lane <lane>`. During: own files only, no version bump / CHANGELOG / roadmap edits (notes in `docs/ai/lanes/<lane>.md` instead; `node tools/lanes.mjs --unstage-shared` before a commit). End: push `lane/<lane>`, `bash tools/session_gate.sh lanedone <lane> lane/<lane>`; if the other lane already shows `LANEDONE` (or has nothing new) in `session_gate.sh status`, continue with the merge step: back on `main`, `bash tools/lane_merge.sh`, apply the notes, one version bump, then End steps 1-6 as usual. Otherwise send no game file (nothing is released yet), short Indonesian summary with tokens, stop.
8. **Mode hemat (owner, 2026-10-19 12:27; CLAUDE.md "Mode hemat"):** read the `Mode hemat` line printed by `session_start.sh` (gate error = treat as ON) and size the session by it (no separate call since v0.69.3). **ON (default):** no team, no worktrees: one main session on the next roadmap item (card head OR U item, alternating as before v0.68); card sessions start at most the one rules-research subagent below, and only when it is needed (skip when low on calls); the player-view subagent (`bs-playwright-tester`) only in a session that makes a backup (End step 3) or changes the UI; skip the team bullets in During/End (no `lane_merge.sh --local`, no A7/A8, no worktree removal). **OFF:** the team below.
9. **Team (HEMAT OFF only; owner, 2026-10-19 07:02; CLAUDE.md "Team session"):** right after step 6, set up and start the agents in the background (Opus, one `Agent` call each, all in one message), then main starts its own head.
   - Worktrees (main runs these, never an agent; no second clone): `git worktree add -q ../wt-ui -B lane/ui origin/main` and `git worktree add -q ../wt-q3 -B lane/q3 origin/main`, each with `ln -s "$PWD/node_modules" ../wt-<x>/node_modules` and `git -C ../wt-<x> config core.hooksPath .githooks`. The pre-commit hook enforces lane files on `lane/*`.
   - A1 UI: the next U item from `roadmap-open.md` item U in `../wt-ui`; lane rules of `docs/ai/lanes/README.md` (own files, `npm run -s loop`, `node tools/lanes.mjs --unstage-shared`, local commits only, shared changes as `- [ ]` notes in `docs/ai/lanes/ui.md`); takes the UI backup/screenshots rules of CLAUDE.md; reports done / notes / test counts.
   - A2 + A3 card prep: the two read-only prep jobs below (sizing; rules/data research).
   - A4 mechanic check: every "(unverified)" row of `docs/reports/mechanic-inventory.md` (grep the engine and glossary, never guess) + one colour deck with `bs-card-data-check`; reports the field values, main writes `data/glossary/mechanics.json`.
   - A5 Q3: the next Q3 step (`roadmap-open.md` "Session order" item 6) in `../wt-q3`, q3-lane files only (`tools/lanes.mjs`); public repo keeps ids, pages, short paraphrases and fingerprints, never full manual text; local commits, notes in `docs/ai/lanes/q3.md`.
   - A6 player-view: skill `bs-playwright-tester` on the current `main` build; failures go to main first.
   - Agent prompts are complete (agents start cold): task, worktree/path, allowed files, "never edit engine/CPU/effect code or shared files, never fetch, push, clone, touch schedules or `session_gate.sh`", report format. Untrusted-input rule applies to what they read.
   - An agent that fails twice: drop its task, note it as `blocked` in `roadmap-open.md`. Low on main calls: skip A4/A5 first, never A6.

## During
- Previous Regression (printed by `session_start.sh`): `failure` = fix it first; `in_progress` = check again before your push.
- Per task: test/scenario first for a new mechanic, `npm run -s loop`, one local commit (the first one also bumps the version and opens the CHANGELOG heading; one version per session). Push once at the end; `git fetch origin main` + rebase before every push.
- HEMAT OFF only: team agents (step 9) report while main works; main applies fixes and commits on `main`. Before the final push: wait for A1/A5 reports, then `bash tools/lane_merge.sh --local` (merges local `lane/ui` and `lane/q3`, prints their notes, rebuilds; exit 4 = conflict: resolve or drop that branch and note it), apply the notes, then start **A7 reviewer** on `git diff origin/main...HEAD -- packages/engine/src data/ tests/` (rules bugs against the cited rules, missing tests; read-only) and fix what it finds before pushing. Scheduled runs: before starting the next task run `bash tools/session_gate.sh switch`; OFF = no new task, go to End.
- **Card-session prep (owner, 2026-10-18 21:56; slimmed in v0.69.3, P0 B4/B5):** (a) **sizing** of the next one or two packs: `python3 tools/pack_plan.py` already sizes them (upper bounds), so with HEMAT ON main runs the one scratch recompile itself (`tools/lever_report.py` or a strip-and-recompile under `build/` or the scratchpad, never `data/` or the engine); no sizing subagent. (b) **rules / card-data research** for the next pack: only when its blocker has no `prep.rules` in `data/glossary/mechanics.json`; then, at the start, one read-only subagent (skill `bs-wiki-rules`: `python3 tools/wiki_rules.py --for "<blocker>"` first; Fandom wiki API, official rules / card list) while main works. Which heads: the pack order of `docs/reports/pack-plan.md`; then, so no kind of card is missed (owner, 2026-10-18 22:38), the highest "Waiting" rows of `docs/reports/mechanic-inventory.md` whose Prep is not `RDL` (item K in `roadmap-open.md`). Main writes the results into `data/glossary/mechanics.json` (`prep.rules`, `prep.data`, `prep.lever`, `status`, `verified: true`, `note`) and the sizes into `docs/ai/roadmap-open.md` in its last commit. HEMAT ON: the (b) subagent, when it runs, also verifies up to 10 "(unverified)" rows; skip it when low on calls. HEMAT OFF: A2 sizes and A3 researches every session (never skipped for tokens); A4 verifies all "(unverified)" rows. Never let them edit code.
- A task that fails twice is dropped, named in the release notes and recorded in `docs/ai/roadmap-open.md` as `blocked (reason, date)`, so the next run takes another item and never repeats it blindly. If every open item is blocked, commit `docs/ai/chain-stop.md`.
- Past ~80 calls: push, handoff comment (done / next / failing seed / tokens used so far), stop and `bash tools/session_gate.sh unlock` (manual and scheduled); the next run continues.
- Usage / quota / rate-limit error: do not retry and do not touch schedules; push what is committed, handoff comment, `bash tools/session_gate.sh unlock`, stop.

## End (in this order)
1. Release gate per `docs/ai/release.md`: push, wait for **CI** only (needed for the GitHub Release), `bash tools/regression_due.sh` and dispatch Regression only on `DUE`, with the sims count it prints (`docs/ai/release.md`) and (HEMAT OFF) start **A8 Regression watcher** in the background (waits for the run, reports pass/fail with the failing lines; `fuzz` failure: download `fuzz-cases`). Continue with steps 2-5; before step 6 read A8's report: a failure is fixed as a patch release in this session (twice failing: note it, the next session fixes it first). Without A8 the next session reads the result (a `fuzz` failure there: download artifact `fuzz-cases`, commit the case, fix it first).
2. `python3 tools/unlock_report.py` (refreshes `docs/reports/unlock-report.md`) and, only when this session changed `data/glossary/mechanics.json` or `data/import` (P0 B6), `python3 tools/mechanic_inventory.py` (refreshes `docs/reports/mechanic-inventory.md`; a mechanic finished this session gets `status: done`, `verified: true` in `data/glossary/mechanics.json` first). Update `docs/roadmap-data.json` (statuses, `updated`, `next`), the `**Next:**` line of the CLAUDE.md Roadmap (the `**Done:**` line is a fixed pointer since v0.69.3: history goes only into `CHANGELOG.md`) (`session_start.sh` prints the Next line, so a stale one misleads the next session) and delete finished items in `docs/ai/roadmap-open.md`; `node tools/gen_roadmap.mjs`, final commit + push.
3. Backup (owner: every 5 releases, not every session, not every commit): newest backup `B=$(git ls-remote --heads origin 'backup/*' | sed 's#.*refs/heads/##' | sort -V | tail -1)`; releases since then `gh api repos/odinguard009/aeterna/compare/$B...main --jq '[.commits[].commit.message | select(test("^v[0-9]"))] | length'` (chore/docs commits do not count). Due when it is >= 5: `git push origin HEAD:refs/heads/backup/vX.Y.Z`. A UI change keeps its own backup of the previous state (CLAUDE.md). Not due: run step 4 with `--no-backup`. Branch housekeeping: keep the newest 3 `backup/v*` branches; older ones whose tip is on `main` are listed with name + SHA in `docs/ai/deleted-branches.md` (restorable with `git push origin <sha>:refs/heads/<name>`); the session proxy blocks branch deletion, so the owner deletes them on GitHub.
4. Deliver the game: copy `index.html` to `/mnt/user-data/outputs/aeterna-vX.Y.Z.html`, then `node tools/session_end_check.mjs` (game file + embedded version, `test:release` on it, mind map fresh, `backup/vX.Y.Z` on origin; `--no-backup` only when no backup is due). It must pass. Since v0.69.3 (P0 B7) it also checks the GitHub Release (`aeterna-vX.Y.Z.html` attached; it runs after CI on `main`, and a docs-only last commit starts no CI, so the release of a version comes from the CI run of its version commit) and prints a `WARN` with the newest Release run when it is missing: after CI finished, a remaining `WARN` = read that run's failing lines and name it in the final message. Then SendUserFile that HTML **and** `docs/roadmap.html` to the owner (owner, 2026-10-16: the playable file must always be sent, not only the mind map). Do not close the session before both files are sent.
5. No scheduling: sessions never create schedules; the next session is either the owner's "Lanjutkan roadmap" or the auto run 30+ minutes later (when the switch is ON). Commit `docs/ai/chain-stop.md` only when the roadmap is empty or every item is blocked.
6. Every session, after both files are sent: (HEMAT OFF) remove the team worktrees (`git worktree remove --force ../wt-ui`, same for `../wt-q3`; unmerged lane work is pushed first as `lane/<x>` so the next session continues it), then `bash tools/session_gate.sh done vX.Y.Z next=Opus` (always Opus since 2026-10-17; this starts the 20-minute idle timer; `unlock` instead on an early stop or error). Name the session "Ver. X.Y.Z" (if no rename tool exists, start the final message with `Ver. X.Y.Z`). Short Indonesian summary that shows `Playable: X / 8,041` (from `tools/unlock_report.py --line`), `Token terpakai: <Token awal minus the total_tokens value left now>` (read the counter after the last tool call; it is the budget-counter difference, effective tokens incl. cache re-reads, so it can differ from the billed figure; the owner can run skill `explain-usage` for a breakdown) the line `Mode otomatis: ON|OFF` (from `bash tools/session_gate.sh switch`) and the line `Mode hemat: ON|OFF` (from `bash tools/session_gate.sh hemat`, read again at the end), and ends with the next session's model hint `gunakan model Opus` (read the next item in `roadmap-open.md`: heavy = Opus, small bundle = Sonnet); after the release, stop (questions go to a new session).
